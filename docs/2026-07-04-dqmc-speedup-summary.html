1. 背景と支配的ボトルネック

DQMC の分配関数は補助場 \(s\) についての和で、各スピン \(\sigma\) の行列式積になる:

\[ Z = \sum_{\{s\}} \prod_{\sigma} \det\!\left( \mathbb{1} + B^{\sigma}_{L} B^{\sigma}_{L-1} \cdots B^{\sigma}_{1} \right), \qquad B^{\sigma}_{l} = e^{-\Delta\tau\,K}\, e^{V^{\sigma}_{l}(s)} \]

等時間 Green 関数 (実装規約 \(g_{ij} = \langle c_i\, c_j^{\dagger}\rangle\)) は

\[ G^{\sigma}(l) = \left( \mathbb{1} + B^{\sigma}_{l}\cdots B^{\sigma}_{1}\, B^{\sigma}_{L}\cdots B^{\sigma}_{l+1} \right)^{-1} \]

低温 (\(\beta=\Delta\tau\,L\) 大) では \(B\) の積が病的条件数になるため、stab 枚ごとに UDV (実装は \(U\,\mathrm{diag}(D)\,T\) 分解) で安定化しながら積を作り直す。旧実装の green_from_scratch は 安定化のたびに \(L\) 枚すべての \(B\) を掛け直していた:

\[ \text{1 sweep のコスト} \;\approx\; O\!\left( \frac{n^3 L^2}{\text{stab}} \right) \;\Longrightarrow\; \beta\text{ 依存が } \beta^2\ \text{則} \]

Mac/Accelerate serial の profile=1 実測 (16×16, \(\beta{=}4\), \(L{=}40\), stab=8) で、1 sweep の 80–87% が green_from_scratch (実体は udv_lmul の QR 連鎖) と特定した。kugui の低温側実行時間爆発は物理ではなく安定化の再計算コストだった。以下はこれを削る順序である。

2. 最適化 (1): UDV 部分積スタック安定化 最大の効果

アイデアと数式

QUEST / ALF 等の標準手法。スイープ前に右側部分積の UDV を stab 境界 \(b_j = j\cdot\text{stab}\) ごとにスタックに保存しておく。実装は suffix スタック:

\[ S[j] = \mathrm{UDV}\big( B(L, b_j) \big) = B_L \cdots B_{b_j+1}, \qquad j = M, M-1, \dots, 1,\quad S[M]=\mathbb{1} \]

スイープが虚時間を進むにつれ、左側の部分積 \(\text{prefix}=B(b_j,0)\) を stab 枚ぶんだけ足し、保存済みの suffix と結合して Green を得る:

\[ G(b_j) = \big( \mathbb{1} + \text{prefix}\cdot S[j] \big)^{-1}, \qquad \text{prefix} \xleftarrow{\ \text{stab 枚 左乗算}\ } \text{UDV} \]

これで安定化あたりの QR は「\(L\) 枚全部」から「stab 枚ぶん + 1 結合」に落ちる:

\[ \#\mathrm{QR}:\ \frac{2L^2}{\text{stab}} \longrightarrow \frac{2L}{\text{stab}} \quad(L\text{ 分の }1),\qquad \text{sweep}:\ O\!\Big(\tfrac{n^3 L^2}{\text{stab}}\Big) \longrightarrow O(n^3 L) \quad(\beta^2 \to \beta\text{ 線形}) \]

コード

suffix スタックの構築 (src/green.c) — 高い \(j\) から低い \(j\) へ、stab 枚ブロック \(B(b_j, b_{j+1})\) を右乗算しながら UDV を積む:

void green_stack_build_suffix(Green *G, GreenStack *st) {
    udv_identity(&st->S[st->M]);
    udv_identity(&st->S[0]);
    for (int j = st->M - 1; j >= 1; j--) {
        const int begin = st->b[j];
        const int len   = st->b[j + 1] - st->b[j];
        green_build_Bblock(G, begin, len, G->B, G->Binv, G->tmp);
        udv_copy(&st->S[j], &st->S[j + 1]);
        udv_rmul(&st->S[j], G->B, &G->work);   /* S[j] = S[j+1] * B_block, QR安定化 */
    }
}

スイープ中の Green 再構成は保存済み suffix と左 prefix を結合するだけ:

int green_from_boundary_factors(Green *G, const UDV *prefix, const UDV *suffix,
                                UDV *combined, int cur_l) {
    udv_combine(prefix, suffix, combined, &G->work);        /* U D T を1回だけ結合 */
    int rc = udv_inv_one_plus_work(combined, G->g, &sgn, &G->work); /* g=(1+UDT)^{-1} */
    ...
}

安定化された \(g = (\mathbb{1} + U\,\mathrm{diag}(D)\,T)^{-1}\) の計算は、\(D\) を大小分割してスケールを分離する標準の well-conditioned 経路 (udv_inv_one_plus_work)。\(\det\) の符号も三角因子から robust に取り、低温でも stale sign を残さない。

3. 最適化 (2): 遅延 (rank-\(k\)) Green 更新

数式

局所フリップ受理ごとの Green 更新は本来 rank-1 (Sherman–Morrison):

\[ G' = G - \frac{N}{d}\, u\, v^{\mathsf{T}}, \qquad u_j = \delta_{ij} - G_{ji},\quad v_k = G_{ik},\quad d = 1 + (1 - G_{ii})\,N \]

これは \(O(n^2)\) の rank-1 (dger 相当) で、\(n{=}256\) ではメモリ帯域律速になり UDV スタック後の相対的支配項になる。そこで \(k\) 回ぶんの更新ベクトルを \(C, V \in \mathbb{R}^{n\times k}\) に溜め、安定化/wrap の直前に 1 回の BLAS3 dgemm でまとめて反映する:

\[ G \leftarrow G - C\,V^{\mathsf{T}} \qquad (\texttt{la\_gemm\_nt\_rect},\ \text{1回の rank-}k) \]

受理判定に必要な対角要素だけは pending 補正を反映して逐次評価する:

\[ \tilde{G}_{ii} = G_{ii} - \sum_{p=1}^{k_{\text{pend}}} C_{ip}\,V_{ip} \;\Longrightarrow\; R = 1 + (1 - \tilde{G}_{ii})\,N \]

コード (src/green.c)

void green_delay_accept(Green *G, int i, double N) {
    const double denom = green_delay_ratio_N(G, i, N);   /* pending込み対角 */
    const double fac   = N / denom;
    for (int j = 0; j < n; j++) {                        /* pending補正した列 */
        double gij = g[j + i*n];
        for (int p = 0; p < G->delay_count; p++) gij -= G->delay_c[j+p*n]*G->delay_v[i+p*n];
        u[j] = ((i==j)?1.0:0.0) - gij;
    }
    ...                                                  /* 同様に v[k] を作り */
    const int p = G->delay_count++;                      /* C,V に積むだけ (即時反映しない) */
    for (int j=0;j<n;j++) G->delay_c[j+p*n] = fac*u[j];
    for (int k=0;k<n;k++) G->delay_v[k+p*n] = v[k];
}
void green_delay_flush(Green *G) {                       /* 溜めた分を一括 rank-k */
    la_gemm_nt_rect(n, G->delay_count, -1.0, G->delay_c, G->delay_v, 1.0, G->g);
    G->delay_count = 0;
}

green_wrap / green_from_scratch / green_from_stack は冒頭・末尾で必ず flush/clear し、pending と厳密再構成が混ざらないよう不変条件を保証している。

4. 最適化 (3): 半充填 PH 対称性 + スタック繰り越し交互スイープ

数式

二部格子・\(\mu{=}U/2\)・\(\lambda\sigma s\) 型 HS 変換では、down スピン Green は up から粒子正孔 (PH) 対称性で厳密に得られる (\(P_i = (-1)^i\) は副格子パリティ):

\[ G^{\downarrow}_{ij} = \delta_{ij} - P_i P_j\, G^{\uparrow}_{ji} \]

up だけ更新すれば安定化・更新・wrap がすべて半分になり、符号も恒等的に 1。さらに「スタック繰り越し交互スイープ」では、前向き/後ろ向きスイープを交互に行い、warmup で作った suffix スタックを次スイープに繰り越すことで、定常状態で green_stack_build の再構築を 0 回にする。後ろ向きには green_wrap_backward (\(G \leftarrow B^{-1} G\, B\)) を使う。

void green_build_ph_down(const Green *up, const int *bipart, double *g_down) {
    for (int j=0;j<n;j++) for (int i=0;i<n;i++) {
        double p = (double)(bipart[i]*bipart[j]);
        g_down[i+j*n] = ((i==j)?1.0:0.0) - p * up->g[j+i*n];   /* δ - P_i P_j G↑_ji */
    }
}

5. 最適化 (4): レプリカ MPI・ハイブリッド並列

16×16 は統計誤差確保に多数レプリカが必要で、これは embarrassingly parallel。独立レプリカを MPI rank に分配し、root で MPI_Gatherv 集約する (src/replica_mpi.c)。ビルドは make dqmc_mpi / dqmc_hybrid。

実測: 純 MPI vs ハイブリッド / スレッド化 BLAS (Genkai, L8 \(U{=}4\) \(\beta{=}8\), nrep120)

結論は「純 MPI レプリカ × sequential MKL が最速」。ノード内スレッド化 BLAS はレプリカ並列に負ける。

6. 最適化 (5): ホットパス微最適化

  • malloc/free 除去: green_update は 1 sweep に \(\sim\!1.4\)万回、作業領域 (\(u/v/\text{tmp}\)) を毎回確保していた。これらを Green / 共有 LinalgWork に事前確保し、ホットパスから動的確保を排除。
  • \(\exp()\) キャッシュ: green_build_B の HS 場は \(s=\pm1\) の 2 値のみ。\(e^{\pm\lambda}\) を事前計算して引く。
  • rank-\(k\) flush の BLAS3 化: 遅延更新の反映を la_gemm_nt_rect (dgemm) に集約し、キャッシュ効率とベクトル化を確保。
  • UDV は factor-only を維持: スタック保存のため中間因子を破棄せず、再利用可能に。
